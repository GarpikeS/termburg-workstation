# 007. Точечное HTTP-исключение для CAMP Dolphin

## Статус

Принято для Workstation `1.1.15` как временное интеграционное исключение.

## Контекст

Dolphin предоставил CAMP API только по адресу `http://85.202.234.197:60888`. Локальные адреса комплекса не отвечают с московской Workstation, а HTTPS endpoint поставщиком не предоставлен. Без отдельного адреса CAMP диагностика типов гостей, услуг, счетов и строк продаж не выполняется.

## Решение

- Разрешить публичный HTTP только для точного origin `http://85.202.234.197:60888`.
- Использовать исключение только в CAMP-клиенте. API штрихкодов и автоматического погашения сохраняет прежний запрет публичного HTTP.
- Передавать CAMP URL отдельным полем `camp.baseUrls`; старые клиенты продолжают использовать локальные адреса.
- Все остальные публичные HTTP и публичные HTTPS адреса в CAMP-клиенте отклонять.
- Не отправлять на центральный сервер исходные строки, значения полей, персональные данные или API-ключ. Heartbeat содержит только безопасный профиль схемы и количества строк.

## Риски и ограничения

HTTP не защищает API-ключ и ответы от перехвата между Workstation и Dolphin. Исключение допустимо только для текущего vendor endpoint и должно быть удалено после появления HTTPS или защищённого VPN-туннеля.

Подключение CAMP остаётся диагностическим: оно подтверждает доступность и структуру, но само по себе не загружает значения в дашборд.

## Проверка и откат

- Unit-тесты подтверждают, что разрешён только точный CAMP origin, а тот же адрес по-прежнему запрещён для API погашения.
- Source-config тест подтверждает раздельные URL основного API и CAMP.
- После выпуска проверяются heartbeat московского устройства, статусы всех четырёх ресурсов и ненулевые количества строк.
- Откат: вернуть прежнюю серверную переменную CAMP URL, перезапустить `termliny-feedback` и установить предыдущую Workstation.
