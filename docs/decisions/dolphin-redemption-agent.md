# ADR: локальный агент погашения билетов Dolphin

## Статус

Принято для пилота.

## Контекст

На рабочем компьютере комплекса CRM Dolphin предоставляет локальный HTTP API и может формировать выгрузку со строками использованных льгот. Постоянного системного администратора нет, а открывать базу Dolphin и входящий порт в интернет небезопасно и операционно сложно.

Сервер `tbgame.ru` уже хранит выданные билеты и поддерживает идемпотентное погашение по точному коду `TB-XXXXXXXX`.

## Решение

Собрать отдельную Windows EXE `Термбург · Dolphin` с модульным ядром:

1. основной адаптер источника обращается к локальному API Dolphin на том же компьютере или в локальной сети; файловый адаптер `.xls`, `.xlsx`, `.csv` остаётся резервным;
2. локальная очередь хранит только код, время погашения и номер операции;
3. транспорт отправляет данные исходящим HTTPS-запросом на отдельный endpoint `tbgame.ru`;
4. сервер принимает только точные коды существующих билетов и повторно их не погашает;
5. Electron-оболочка даёт одну понятную панель состояния и может быть позже заменена или встроена в другую EXE без изменения ядра.
6. установщик содержит одноразовый пропуск автоактивации: при первом запуске он обменивается на отдельный 256-битный ключ компьютера, после чего больше не принимается сервером.
7. сервер выдаёт ключ локального API только авторизованному устройству по HTTPS; агент держит его только в памяти и не записывает на диск.
8. первый запуск API работает в диагностическом режиме: агент передаёт только техническую сводку схемы и количества строк, а погашение включается серверной настройкой после проверки.

## Числовые ограничения пилота

- сканирование папки: сразу при запуске и каждые 300 секунд;
- HTTP timeout: 10 секунд;
- не более 2 сетевых попыток за один цикл, пауза 1 и 3 секунды с jitter до 500 мс;
- пакет отправки: до 200 строк;
- сервер принимает до 2 000 строк и 256 КиБ за запрос;
- файл выгрузки: до 20 МиБ и до 10 000 строк;
- неизвестные серверу коды сохраняются в очереди и повторяются до 7 суток;
- журнал приложения ротируется при 2 МиБ, хранится один предыдущий файл.

Значения выбраны как консервативные эмпирические defaults для пилота с единицами выгрузок в день. После двух недель эксплуатации их нужно пересмотреть по журналам.

## Безопасность

- входящие порты Dolphin не публикуются в интернете; агент обращается к `127.0.0.1` или приватному адресу локальной сети;
- у EXE отдельный токен только на импорт погашений, административный токен в программу не попадает;
- постоянный серверный токен в публичный установщик не встраивается;
- ключ локального API не встраивается в установщик, не сохраняется в настройках агента и не передаётся в heartbeat;
- ключ компьютера генерируется на самом компьютере и хранится через Windows DPAPI (`Electron safeStorage`);
- сервер хранит только SHA-256 хеши одноразового пропуска и ключа компьютера;
- активация идемпотентна для того же компьютера и отклоняет попытку использовать установщик на другом компьютере;
- в сервер и журналы не передаются имя, телефон, возраст и другие поля выгрузки;
- нет fuzzy-сопоставления: повреждённый или укороченный код не погашается автоматически;
- выключение фоновой синхронизации доступно одним переключателем.

## Альтернативы

### Открыть порт Dolphin в интернет

Отклонено: нужен сетевой администратор, статический маршрут и защита API. Увеличивается blast radius при компрометации. Используется только локальное подключение с рабочего компьютера.

### Ручная загрузка каждого XLS на сервер

Оставлена как резервный путь. Она надёжна, но требует действий сотрудника и не даёт своевременного погашения.

### Автоматически нажимать кнопки в интерфейсе Dolphin

Отложено. UI-робот зависит от расположения окон и версии Dolphin. Будет использован только если невозможно настроить файловую выгрузку или read-only доступ.

## Trade-offs

- для чтения старого `.xls` нужен установленный Microsoft Excel; CSV читается без Excel;
- установщик предназначен для одного рабочего компьютера; для второго компьютера нужна новая сборка с новым одноразовым пропуском;
- папка `Загрузки`, проверка каждые 5 минут и запуск вместе с Windows включаются автоматически;
- фактическая схема ответа API Dolphin проверяется первым диагностическим heartbeat; до подтверждения автопогашение выключено.

## Проверка и откат

- unit-тесты проверяют точное извлечение кода, отсутствие fuzzy-погашения, дедупликацию и очередь;
- интеграционный тест проверяет отдельный серверный токен и повторную отправку;
- интеграционный тест проверяет одноразовую, идемпотентную и привязанную к устройству активацию;
- тест локального API проверяет `X-API-Key`, оба варианта `datebegin`, запрет публичного HTTP и отсутствие погашения без времени входа;
- packaged smoke-test читает предоставленный XLS без отправки данных;
- отключение автозапуска и завершение программы полностью прекращают обмен;
- ручной серверный импорт остаётся доступным как fallback.
