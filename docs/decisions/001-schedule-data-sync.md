# ADR-001: единый JSON-контракт и локальный HTTP-сервер

- **Статус:** accepted for MVP
- **Владелец:** Термбург / инженер сайта
- **Дата:** 2026-08-06

## Решение

Все клиенты читают один контракт `ScheduleData schemaVersion=1`. На одном компьютере запускается небольшой Node.js-сервер: `GET /api/schedule` для экранов и `PUT /api/schedule` для редактора. Запись идёт через временный файл и rename; клиенты имеют fallback на `localStorage` и встроенный seed.

## Контекст и границы доказательств

- Факт из репозитория: текущее приложение — статический React/Vite SPA без backend.
- Факт из запроса: один компьютер должен обновлять все экраны в общей сети.
- Принципы: аддитивная эволюция API [A3 Building Microservices, гл. 5], деградация на периферии [A7 Release It!, гл. 4], минимальные права [A13 Building Secure & Reliable Systems, гл. 5].

## Рассмотренные варианты

| Вариант | Время запуска | Общая сеть | Сайт | Операционная сложность | Решение |
|---|---:|---:|---:|---:|---|
| Только `localStorage` | минимально | нет | нет | низкая | отклонён: не выполняет главное требование |
| Локальный Node.js + JSON | низкое | да | через тот же API-контракт | умеренная | **выбрано** |
| Сразу облачная БД | среднее | да | да | выше, нужны учётки/секреты/мониторинг | отложено до подключения сайта |

## Trade-offs

1. Выигрываем быстрый запуск и отсутствие внешней зависимости, но принимаем single-computer risk: при выключенном хосте экраны остаются на последнем кэше.
2. JSON прост для резервной копии, но не подходит для одновременной работы нескольких редакторов.

## Guardrails и проверки

- HTTP request timeout: 10 с; client read timeout: 2.5 с; save timeout: 5 с. `[empirical: локальная сеть, малый JSON]`
- Polling: 5 с для ТВ, 15 с для обычного клиента. `[empirical: acceptance criteria MVP]`
- Maximum write payload: 2 МБ. `[empirical: текущий seed < 20 КБ и более 100× запас]`
- Write endpoint проверяет схему; опциональный `SCHEDULE_ADMIN_TOKEN` закрывает PUT. Без токена режим разрешён только для доверенной LAN.

## Риски

| Риск | Severity | Владелец | Митигация |
|---|---|---|---|
| Компьютер-хост выключен | medium | администратор комплекса | автозапуск и локальный fallback; следующий этап — облако |
| Неавторизованное изменение в LAN | high | инженер сайта | задать `SCHEDULE_ADMIN_TOKEN` перед боевым запуском |
| Ошибка персонала | medium | контент-менеджер | валидация форм и JSON-копия; следующий этап — история версий |

## Точка пересмотра

Перенести хранилище в облачную БД, когда одновременно выполняется всё: **(1)** нужен публичный сайт извне LAN, **AND (2)** редакторов больше одного, **AND (3)** нужна история изменений/откат.
