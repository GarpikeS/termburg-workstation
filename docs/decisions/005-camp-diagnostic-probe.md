# 005. Безопасная диагностика CAMP API

## Статус

Принято для версии Workstation `1.1.12`.

## Контекст

Dolphin предоставил новые CAMP endpoints `guesttypes`, `services` и `accounts`. Фактическая схема ответов ещё не подтверждена, а `accounts` может содержать персональные и финансовые данные. До построения импорта нужно проверить доступность endpoints из локальной сети комплекса и получить только структуру данных.

## Решение

Workstation выполняет отдельную диагностическую проверку CAMP API:

- `guesttypes` и `services` запрашиваются с начальной датой обмена `2023-09-01`;
- `accounts` запрашивается дважды: с датой `2023-09-01` и с текущей датой по московскому времени;
- для `accounts` дата считается датой счёта, а не техническим watermark обновлений;
- в heartbeat отправляются только технический результат запроса, количество строк, размер ответа, разрешённые по метаданным имена и типы полей, доля `null` и хеш схемы; неизвестные ключи заменяются коротким SHA-256-префиксом;
- исходные значения строк, API-ключи и персональные данные не сохраняются, не журналируются и не отправляются на сервер;
- проверка выполняется не чаще одного раза в сутки, кроме явного ручного запуска.

Проверка является только диагностической. Она не заполняет дашборд и не создаёт финансовые показатели.

## Финансовая семантика

Поле `BALANCE` в `accounts` нельзя считать выручкой без подтверждённого описания схемы и сверки с фискальными данными. Для подтверждённой выручки ожидается отдельный источник чеков или оплат, например `CAMP_KKMCHEQUES`, `CAMP_ACCOUNTPAYMENTS` либо `CAMP_ACCOUNTSALES`.

## Безопасность и ограничения

- CAMP API вызывается только через установленную Workstation в локальной сети комплекса;
- публичный незашифрованный HTTP-адрес не разрешается как источник;
- редиректы отключены, размер ответа и количество строк ограничены;
- новый импорт будет включён только после проверки реальной схемы и явного списка разрешённых полей.

## Следующий шаг

После успешной диагностики зафиксировать контракт каждого ответа, определить безопасные агрегаты и отдельно согласовать правила расчёта посетителей, продаж, возвратов и выручки. Только после этого реализовать нормализацию и загрузку данных в дашборд.
