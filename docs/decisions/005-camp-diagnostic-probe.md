# 005. Безопасная диагностика CAMP API

## Статус

Принято для версии Workstation `1.1.13`.

## Контекст

Dolphin предоставил CAMP endpoints `guesttypes`, `services`, `accounts` и `accountSales`. Фактическая схема ответов ещё не подтверждена, а `accounts` и `accountSales` могут содержать персональные и финансовые данные. До построения импорта нужно проверить доступность endpoints из локальной сети комплекса и получить только структуру данных.

## Решение

Workstation выполняет отдельную диагностическую проверку CAMP API:

- `guesttypes` и `services` запрашиваются с начальной датой обмена `2023-09-01`;
- `accounts` запрашивается дважды: с датой `2023-09-01` и с текущей датой по московскому времени;
- `accountSales` запрашивается дважды: с датой `2023-09-01` и с текущей датой по московскому времени;
- один цикл диагностики включает шесть запросов;
- для `accounts` дата считается датой счёта, а не техническим watermark обновлений;
- для `accountSales` смысл `dateexchange`, а также коды продаж, возвратов и отмен остаются неподтверждёнными;
- в heartbeat отправляются только технический результат запроса, количество строк, размер ответа, разрешённые по метаданным имена и типы полей, доля `null` и хеш схемы; неизвестные ключи заменяются нейтральной меткой, а адрес локального источника не передаётся;
- исходные значения строк, API-ключи и персональные данные не сохраняются, не журналируются и не отправляются на сервер;
- проверка выполняется не чаще одного раза в сутки, кроме явного ручного запуска.

Проверка является только диагностической. Она не заполняет дашборд и не создаёт финансовые показатели.

## Финансовая семантика

Поле `BALANCE` в `accounts` и поле `SUMMA` в `accountSales` нельзя считать фискальной выручкой без подтверждённого описания схемы и сверки. Для подтверждённой выручки требуется сопоставление строк продаж с чеками или оплатами, например `CAMP_KKMCHEQUES` и `CAMP_ACCOUNTPAYMENTS`, а также согласование правил скидок, возвратов и отмен.

## Безопасность и ограничения

- CAMP API вызывается только через установленную Workstation в локальной сети комплекса;
- публичный незашифрованный HTTP-адрес не разрешается как источник;
- редиректы отключены, размер ответа и количество строк ограничены;
- новый импорт будет включён только после проверки реальной схемы и явного списка разрешённых полей.

## Следующий шаг

После успешной диагностики зафиксировать контракт каждого ответа, подтвердить семантику `dateexchange` и кодов возврата/отмены для `accountSales`, определить безопасные агрегаты и сверить строки продаж с оплатами или фискальными чеками. Только после этого согласовать правила расчёта посетителей, продаж, возвратов и выручки, а затем реализовать нормализацию и загрузку данных в дашборд.
