# Термбург: единое рабочее место

`Termburg-Workstation-<Complex>-Setup-*.exe` объединяет редактор расписания и фоновую синхронизацию Dolphin. Сотрудник устанавливает один EXE; Node.js, отдельный агент и ручной ввод API-ключей не нужны.

## Обновления программы

Начиная с версии `1.1.0`, Workstation проверяет стабильные релизы отдельного репозитория `GarpikeS/termburg-workstation`. При наличии новой версии программа скачивает установщик, проверяет SHA-256 и предлагает обновиться. Расписание, настройки публикации и зашифрованный ключ Dolphin хранятся в профиле Windows и не удаляются.

Начиная с версии `1.1.1`, установленная Workstation регистрируется в автозагрузке до запуска локального сервера расписания. При входе в Windows она запускается с аргументом `--background`, не открывает редактор и остаётся доступной через значок в системном трее. Это работает независимо от подключения Dolphin и даже если порт расписания временно занят.

Начиная с версии `1.1.14`, первичный установщик содержит только подключение и локальный аккаунт выбранного комплекса. Московский пакет не содержит доступов Зеленогорска и наоборот. Публичное обновление не содержит site-sync, паролей, password verifier или enrollment-token; оно сохраняет уже настроенный профиль Windows.

При первичной установке профиль выбранного комплекса заменяет прежние подключения и локальные аккаунты других комплексов, если они были перенесены со старой программы. Сохранённые расписание и история публикаций выбранного комплекса остаются.

Начиная с версии `1.1.13`, Workstation диагностирует CAMP endpoints Dolphin, включая строки продаж `accountSales`. Эта проверка не импортирует исходные строки и не заполняет дашборд: на сервер уходит только безопасный профиль схемы и количества строк. Подробности зафиксированы в [ADR 005](decisions/005-camp-diagnostic-probe.md).

Начиная с версии `1.1.15`, CAMP использует отдельный список адресов. Для выданного Dolphin origin `http://85.202.234.197:60888` действует точечное временное исключение; основной API штрихкодов по-прежнему не принимает публичный HTTP. Решение и риск описаны в [ADR 007](decisions/007-camp-vendor-http-exception.md).

Начиная с версии `1.1.17`, кнопка обновления запускает проверенный NSIS-установщик напрямую, без скрытого PowerShell-посредника. Установщик получает штатные флаги `--updated` и `--force-run`, поэтому после тихой установки новая версия открывается автоматически.

Первичная установка выполняется только комплексным установщиком `Termburg-Workstation-<Complex>-Setup-*.exe`, переданным напрямую по закрытому каналу. Его нельзя публиковать в GitHub или в обычном статическом каталоге сайта: внутри есть одноразовая активация и полномочия выбранного комплекса. Публичный файл `Termburg-Workstation-Update-*.exe` предназначен только для уже активированного компьютера.

Сборка публичного обновления:

```powershell
npm run workstation:update-exe
```

Релиз должен иметь тег `workstation-vX.Y.Z` и два файла: EXE и соответствующий `.sha256`.

## Установка

1. Закройте отдельные программы «Термбург Расписание» и «Термбург Dolphin», если они запущены.
2. Запустите установщик и подтвердите предупреждение SmartScreen, если оно появится.
3. Откройте ярлык «Термбург Рабочее место».
4. В трее Windows проверьте строку Dolphin. После первой проверки она должна сообщать, что связь установлена или автоматическое погашение работает.

Программа сама запускается вместе с Windows. При автозапуске окно не мешает сотруднику: расписание и Dolphin продолжают работать в фоне, а редактор открывается через значок в трее.

## Перенос существующих данных

При первом запуске программа копирует существующее расписание и настройки публикации из `%APPDATA%\Термбург Расписание`. Если на компьютере уже был активирован отдельный агент Dolphin, его защищённые настройки и состояние копируются из `%APPDATA%\Термбург · Dolphin`. Существующие файлы нового приложения не перезаписываются.

После успешной проверки объединённой программы отдельные старые приложения надо убрать из автозапуска или удалить, чтобы они не запускались параллельно.

## Диагностика

- Значок в трее → `Проверить Dolphin сейчас` запускает проверку вручную.
- Значок в трее → `Открыть журнал Dolphin` открывает папку с `dolphin-agent.log`.
- Расписание продолжает работать на порту `4174` по тем же адресам, что и отдельная программа.
- Один zero-config установщик активирует один новый рабочий компьютер. Для следующего компьютера выпускается новая сборка.

### Диагностическая проверка CAMP

Workstation `1.1.13` и новее проверяет CAMP API только из локальной сети комплекса. За один цикл выполняются шесть запросов:

- `guesttypes` — `dateexchange=2023-09-01`;
- `services` — `dateexchange=2023-09-01`;
- `accounts` — отдельно `dateexchange=2023-09-01` и текущая дата по Москве;
- `accountSales` — отдельно `dateexchange=2023-09-01` и текущая дата по Москве.

У `accounts` параметр `dateexchange` трактуется как дата счёта. Для `accountSales` семантика `dateexchange`, а также признаки продажи, возврата и отмены пока не подтверждены Dolphin. Проверка выполняется раз в сутки; команда `Проверить Dolphin сейчас` может запустить её вне расписания.

В центральный heartbeat попадают только статус, даты запросов, количество строк и профиль схемы: разрешённые по метаданным имена полей, их типы, количество `null` и хеш. Неизвестные ключи заменяются нейтральной меткой без исходного имени; адрес локального источника также не передаётся. Значения полей, персональные данные и API-ключ не передаются. В журнале также не должно быть исходных строк.

Успешная проверка подтверждает только доступность и форму ответа. `BALANCE` из `accounts` и `SUMMA` из `accountSales` не считаются фискальной выручкой. Финансовый показатель можно включить лишь после сверки строк продаж с чеками или оплатами (`CAMP_KKMCHEQUES`, `CAMP_ACCOUNTPAYMENTS`) и согласования правил скидок, возвратов и отмен.

При проверке результата:

1. убедитесь, что московская Workstation получила актуальную версию и отправила новый heartbeat;
2. проверьте статус каждого из шести запросов и количество строк;
3. сравните имена и типы полей с метаданными Dolphin;
4. не копируйте исходные ответы `accounts` и `accountSales` в журнал или чат;
5. до утверждения allowlist полей оставьте импорт в дашборд выключенным.

## Сборка

```powershell
npm run workstation:moscow-exe
```

Для Зеленогорска используется `npm run workstation:zelenogorsk-exe`. Установщик, SHA-256 и хеш одноразовой активации появляются в `release/workstation`. Секрет активации удаляется из исходного дерева после сборки и игнорируется Git. Сборку выполняют только из чистого Git worktree; каталог `workstation/generated` очищается до и после сборки.

Перед первым запуском нового компьютера на Numera резервируют `feedback.env` и `dolphin-connectors.json`, затем атомарно заменяют только `DOLPHIN_ENROLLMENT_TOKEN_HASH` значением из соответствующего `workstation-<complex>-enrollment.sha256`. `DOLPHIN_CONNECTOR_TOKEN` и хранилище устройств не меняют. После перезапуска проверяют активность сервиса и отказ `401` для заведомо неверной активации; настоящий одноразовый token запросом не проверяют. При ошибке возвращают резервную копию `feedback.env` и перезапускают сервис.
